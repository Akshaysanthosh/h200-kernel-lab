# Reproducing and reviewing the work

## 1. CPU-only review

```bash
git clone https://github.com/Akshaysanthosh/h200-kernel-lab.git
cd h200-kernel-lab
python3 scripts/verify_artifacts.py
python3 scripts/summarize_results.py
```

The verifier checks protected source hashes, Python syntax without imports, JSON validity and curated documentation links. It does not compile CUDA or prove numerical correctness. Read the source/result pair in `docs/RESULTS.md`.

## 2. Environment for GPU development

An NVIDIA H200 and a compatible CUDA development toolchain are required to meaningfully reproduce the reported comparisons. A Mac can prepare files and invoke remote jobs but cannot run these Hopper kernels locally.

The later lab uses `lmsysorg/sglang:dev-muse-spark-open`, plus NumPy and Ninja. The public implementation expects CUDA13-era cuBLASLt, with fixed-plan support observed at version 130101. This image tag is mutable: record the resolved image digest and runtime library versions for any new run. Earlier CUDA12.8 experiments are historical evidence, not a compatible reproduction recipe for the current champion.

For Modal orchestration, use a separate virtual environment:

```bash
python3 -m venv .venv-modal
.venv-modal/bin/pip install 'modal==1.6.3'
cd muse_bf16_proj
../.venv-modal/bin/python modal_lab/run_candidate.py candidates/public/v18_sk2_m32.py --mode public_refine
```

Without `--execute`, this is a local hash/preservation dry run. It does not launch GPU compute.

Some experimental modes require CUTLASS headers. Fetch the recorded revision yourself:

```bash
mkdir -p vendor
git clone --branch v3.9.2 --depth 1 https://github.com/NVIDIA/cutlass.git vendor/cutlass
git -C vendor/cutlass rev-parse HEAD
```

Confirm it matches `ad7b2f5e84fcfa124cb02b91d5bd26d238c0459e` before using those experiments. The dependency checkout is not vendored into this portfolio.

## 3. Free-credit launch gate

Authenticate your own Modal workspace and profile `okc-free`. Before each execution, inspect the provider dashboard, confirm applicable free credits and a server-side **$0 net spending cap**, and confirm the CLI points to that workspace. Do not treat a local JSON file as a billing guarantee.

The runner requires a recent `results/modal/billing-verified.json` record with these fields, filled only from actual observations:

```json
{
  "workspace": "YOUR_VERIFIED_WORKSPACE",
  "verified_at": "CURRENT_UTC_ISO8601_TIMESTAMP",
  "spend_limit_usd": 0,
  "remaining_compute_credits_usd": 0,
  "cli_workspace_verified": false,
  "cli_profile": "okc-free"
}
```

The zero-credit/false example intentionally cannot authorize a run. The runner requires at least $3 free credits and verification less than one hour old. No billing record or credentials are included here. Free-credit availability is account-dependent, not guaranteed by this repository.

After real verification, adding `--execute` launches a bounded job and may consume credits, including image-build costs. The runner limits a function to one H200, 900 seconds and zero retries. Recheck charges and active applications afterwards. Choose modes using their corresponding report; not every historical candidate belongs on the current image.

## 4. Official validation

A person must accept challenge rules and authenticate their own `okc` CLI. Check current free quota first. The archived `tools/run_lt_check.py` contains a workstation-specific CLI path and dated scheduling constraints; adapt those locally before reuse, or use the official CLI directly:

```bash
okc problems --json
okc check candidates/public/nathen_v18_linear.py --json
```

This consumes a free check if available. Do not use scored submissions as substitute validation. Review all correctness tests, integrity flags, preparation time and profiles. Duplicate check responses are not independent measurements.

Scored submission is a separate deliberate action. Always submit the exact source that passed validation; the root `submission.py` is the old 1.22741× artifact, not the current champion.

## Limits of reproduction

This is a research snapshot, not a one-command production package. It includes historical evaluators and experiments with different assumptions. Some scripts refer to excluded raw logs or local paths. Use the curated guide and current candidate paths rather than executing every archived script. Synthetic workload inputs are generated by the supplied challenge reference; no model weights or private activations are distributed.
